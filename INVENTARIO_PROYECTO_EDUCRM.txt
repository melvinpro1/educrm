--------------------------------------------------------------------------------
2.1 LOGIN (Login.jsx)
--------------------------------------------------------------------------------
Propósito: Página de autenticación para iniciar sesión

CAMPOS DEL FORMULARIO:
  - Correo electrónico o Usuario (text, requerido)
  - Contraseña (password, requerido)

BOTONES:
  - "Continuar con Google" (botón secundario - no implementado actualmente)
  - "Iniciar sesión" (tipo submit)
  - Enlace "Regístrese aquí" → navega a página de Registro

VALIDACIONES:
  - Verifica que los campos no estén vacíos
  - Muestra mensaje de error si las credenciales son incorrectas

PROCESO:
  1. Usuario ingresa username y password
  2. Llama a login(username, password) del API
  3. Backend retorna { token, user }
  4. Guarda token en localStorage como "authToken"
  5. Guarda user en localStorage como "user" (JSON)
  6. Redirecciona a Home

--------------------------------------------------------------------------------
2.2 REGISTRO (Registro.jsx)
--------------------------------------------------------------------------------
Propósito: Página de registro de nuevos usuarios

CAMPOS DEL FORMULARIO:
  - Nombre (text, opcional)
  - Apellido (text, opcional)
  - Nombre de Usuario (text, requerido)
  - Correo Electrónico (email, requerido)
  - Contraseña (password, mínimo 6 caracteres, requerido)
  - Confirmar Contraseña (password, requerido)

VALIDACIONES:
  - Las contraseñas deben coincidir
  - Email debe ser válido (regex: /^[^\s@]+@[^\s@]+\.[^\s@]+$/)
  - Contraseña mínimo 6 caracteres
  - Todos los campos requeridos deben estar llenos

BOTONES:
  - "Registrarse" (tipo submit)
  - Enlace "Inicie sesión aquí" → volver a Login

--------------------------------------------------------------------------------
2.3 HOME / PANEL PRINCIPAL (Home.jsx)
--------------------------------------------------------------------------------
Propósito: Panel principal con estadísticas del sistema

SECCIONES:
  - Encabezado con título y fecha actual del sistema
  - 4 Tarjetas de KPIs/Estadísticas:
      * Total Estudiantes Activos
      * Total Encargados
      * Comunicaciones Enviadas
      * Total Correos
  - Gráfico Pie Chart: distribución por nivel académico
      * Cuarto Nivel (badge violeta)
      * Quinto Nivel (badge verde)
  - Resumen de actividad (4 items)
  - Historial de transacciones/acciones (tabla dinámica)

TIPOS DE ACCIONES EN HISTORIAL:
  - crear    → icono "+"
  - editar   → icono lápiz
  - eliminar → icono basura
  - enviar   → icono sobre/envío

DATOS QUE CONSUME:
  - getDashboardStats() retorna:
      * estudiantes_activos
      * estudiantes_totales
      * encargados_totales
      * comunicaciones_enviadas
      * correos_totales
      * estudiantes_por_nivel: [{ nombre, valor }]
  - getHistorialAcciones() retorna:
      * id
      * tipo_accion
      * descripcion
      * detalles
      * usuario
      * fecha_hora

  - Correo Institucional (email, requerido)
  - Correo Personal (email, opcional, debe ser distinto al institucional)
  - Teléfono (formato ####-####, opcional)
  - Colegio de procedencia (autocomplete con lista de colegios CR)

  - Nombre del Encargado (text, requerido)
      * Deshabilitado en modo edición (read-only)
  - Correo del Encargado (email, requerido)
      * Deshabilitado en modo edición (read-only)
  - Teléfono del Encargado (formato ####-####)
      * Deshabilitado en modo edición (read-only)

VALIDACIONES:
  - Formateo automático de cédula (#-####-####)
  - Formateo automático de teléfono (####-####)
  - Validación de cédula duplicada vía API
  - Los correos institucional y personal deben ser diferentes
  - En edición: datos del encargado son solo lectura

BOTONES:
  - "Cancelar" → regresa a la lista
  - "Guardar" (modo nuevo) / "Actualizar" (modo editar) → envía el formulario

5. API / ENDPOINTS FRONTEND (src/api/)
================================================================================

--------------------------------------------------------------------------------
5.1 auth.js — Autenticación
--------------------------------------------------------------------------------

POST /api/auth/register/
  Payload: { username, email, password, first_name, last_name }
  Retorna: { token, user }

POST /api/auth/login/
  Payload: { username, password }
  Retorna: { token, user }

POST /api/auth/logout/
  Retorna: { detail }

Funciones exportadas:
  register(userData)      - registra nuevo usuario
  login(username, password) - inicia sesión, guarda token
  logout()                - cierra sesión, limpia localStorage
  isAuthenticated()       - verifica si existe authToken en localStorage
  getCurrentUser()        - parsea "user" desde localStorage
  getAuthToken()          - devuelve el token almacenado

--------------------------------------------------------------------------------
5.2 estudiantes.js
--------------------------------------------------------------------------------

GET  /api/estudiantes/?estado=activos|inactivos|todos

10. AUTENTICACIÓN / LOGIN — DETALLE COMPLETO
================================================================================

FRONTEND — Proceso de Login:
  1. Usuario ingresa: correo/usuario + contraseña
  2. Valida que ambos campos estén llenos
  3. Llama a login(username, password)
  4. Backend autentica y retorna { token, user }
  5. Frontend guarda en localStorage:
       "authToken" → string del token
       "user"      → JSON.stringify(user)
  6. Redirecciona al Home

VERIFICACIÓN DE SESIÓN:
  isAuthenticated()  → retorna true si existe "authToken" en localStorage
  getCurrentUser()   → parsea JSON del "user" en localStorage
  getAuthToken()     → devuelve el string del token

BACKEND — Endpoints de autenticación:

  POST /api/auth/register/
    Payload:
      { username, email, password, first_name, last_name }
    Validaciones:
      - username, email, password requeridos
      - password mínimo 6 caracteres
      - username no duplicado
      - email no duplicado
    Response 201:
      { token, user: { id, username, email, first_name, last_name, is_staff, is_superuser } }

  POST /api/auth/login/
    Payload:
      { username, password }
    Response 200:
      { token, user }
    Errors:
      400 → faltan campos
      401 → credenciales incorrectas o usuario inactivo

  POST /api/auth/logout/
    Response 200:
      { detail: "Sesión cerrada exitosamente" }

  Implementación de Token:
    - Usa rest_framework.authtoken.models.Token de Django REST Framework
    - El token se crea automáticamente al registrar el usuario
    - Se obtiene o crea al hacer login (get_or_create)
    - Se envía en cada request: Authorization: Token {token}
